## 1. 动机

M4 每次仅研究一个效率缺陷。这对推导过程很有用，但容易导致模型比较出现偏差。一个模型可能具有稀疏计算特性，但仍需要庞大的驻留权重集。两个模型的激活参数量可能相同，但 KV-cache 流量却大相径庭。循环比率的改变可能会影响服务路径，而无需更改词表或损失函数。

M5 通过为每个模型提供一张架构卡片来修正这一记账缺陷。该卡片并非排行榜条目，而是对设计选择、成本及未知因素进行溯源控制的记录。

本课中的示例是一张教学地图。它们并不声称谱系图中的优势证明了直接复制关系或完整的历史谱系。特定于模型的字段仅在附加了技术报告、模型卡片或配置 URL 后，才应填入 M5.2。

## 2。卡片定义

每张卡片使用相同的字段：

| 字段 | 必需内容 |
| --- | --- |
| 身份标识 | 名称、发布日期、总/活跃参数量、层数、$d_{\mathrm{model}}$、头数、$h_{\mathrm{kv}}$、词表、上下文长度、许可证 |
| 注意力变体 | MHA、GQA、MQA、MLA、稀疏或混合；窗口方案；Sink 机制；QK-norm |
| 位置编码 | RoPE base 和 partial-RoPE 比例、NoPE 层数、ALiBi，或其他长上下文方法 |
| 归一化位置 | Pre、Post 或 Sandwich；LayerNorm、RMSNorm 及 QK-norm |
| FFN 或 MoE | 激活函数；稠密宽度；总/活跃/共享专家数；路由与平衡机制 |
| 残差结构 | 标准型、多流/超连接，或其他明确引用的形式 |
| 额外目标 | MTP、辅助损失，或明确未知 |
| 数值精度 | 训练精度和推理量化 |
| 循环性 | 无，或线性注意力/SSM 层及其与注意力层的比例 |
| 来源 | 技术报告、模型卡片及配置 URL |

卡片中的符号保留其 M4 含义。例如，$h_{\mathrm{kv}}$ 表示独立键值头数，$d_h$ 表示头宽，$L$ 表示层数。卡片不得静默地将 $h$ 替换为 $h_{\mathrm{kv}}$。

## 3. 来源与谱系

每个字段具有三种状态之一：

1. **已验证。**该字段陈述于主要技术报告、模型卡片或发布的配置中，且卡片直接链接至该来源。
2. **未知。**公开来源未陈述该字段，或尚未检查该来源。“未知”是一个有效结果。
3. **推导得出。**该字段是根据已验证字段，利用早期课程（如 M3.5/M4.3中的缓存字节）计算得出的。卡片会记录公式及其输入。

切勿根据 API 行为推断私有模型的归一化位置、专家数量、RoPE 基数或循环比率。“类 Transformer"并非任何单个卡片字段的值。如果报告仅提供家族级描述，请将未报告的字段保留为未知。

谱系中每个 M4 设计轴对应一条边。根引用是 [Attention Is All You Need](https://arxiv.org/abs/1706.03762)。缓存/路由分支使用 [DeepSeek-V2 report](https://arxiv.org/abs/2405.04434)和 [DeepSeek-V3 report](https://arxiv.org/abs/2412.19437)。循环分支使用 [Mamba](https://arxiv.org/abs/2312.00752)和 [Qwen3 report](https://arxiv.org/abs/2505.09388)。开源权重注意力/MoE 示例使用 [gpt-oss model card](https://openai.com/index/gpt-oss-model-card/)。稀疏注意力示例链接至 [DeepSeek-V3.2 report](https://arxiv.org/abs/2512.02556)。当前架构来源未经过验证的节点，显示为未知来源状态，而非猜测的卡片。

其他命名节点也有直接的主要引用：[GPT-2](https://openai.com/index/better-language-models/)、[Llama](https://arxiv.org/abs/2302.13971)、[Mistral](https://arxiv.org/abs/2310.06825)、[Gemma 3](https://arxiv.org/abs/2503.19786)以及 [Qwen3-Next model card](https://huggingface.co/Qwen/Qwen3-Next-80B-A3B-Instruct)。Kimi K2/K3、DeepSeek-V4 和分组 SSM 混合节点在尚未附加当前主要架构文档时，在组件中明确保持来源门控状态。

教学边如下：

| 边 | M4 轴可视化内容 |
| --- | --- |
| Transformer → GPT-2/Llama | 解码器自注意力与位置选择 |
| Transformer → Mistral/Gemma 3/gpt-oss | 局部或交替窗口注意力 |
| Transformer → DeepSeek-V2/V3 | MLA 缓存压缩加稀疏 MoE |
| DeepSeek-V3 → DeepSeek-V3.2 | 稀疏查询/键选择 |
| DeepSeek-V3.2 → DeepSeek-V4 | 压缩注意力与多流残差选择；来源状态需在卡片中检查 |
| DeepSeek-V2 → Kimi K2/K3 | 潜在缓存与稀疏路由设计轴 |
| Transformer → Qwen3 → Qwen3-Next | GQA/MoE 后接循环/注意力混合 |
| Mamba → Qwen3-Next and SSM hybrids | 选择性状态空间循环 |

这是 V-M5-a显示的数据。按年份或轴过滤会改变可见的边；它不会重写任何卡片。组件的边标签说明了正在比较的设计轴，而非已证实的历史影响。

## 4。数值验证

该卡片区分了总参数量、激活参数量和缓存状态。一个精确的派生字段是 KV 缓存字节数：

$$
B_{\mathrm{KV}}
=2L\,n\,h_{\mathrm{kv}}\,d_h\,b
\quad\text{bytes},
$$

其中 $L$ 为层数，$n$ 为缓存序列长度，$h_{\mathrm{kv}}$ 为独立 KV 头数量，$d_h$ 为头宽度，$b$ 为每个存储标量的字节数。因子 $2$ 用于计数键（keys）和值（values）。这是在所述缓存布局下的会计恒等式，而非关于特定内核临时缓冲区的声明。

对于 $L=32$、$n=4096$、$h_{\mathrm{kv}}=8$、$d_h=128$ 和 $b=2$：

$$
B_{\mathrm{KV}}
=2\cdot32\cdot4096\cdot8\cdot128\cdot2
=536{,}870{,}912\ \text{bytes}
=512\ \text{MiB}.
$$

在维度相同但采用 MHA 的 $h_{\mathrm{kv}}=32$ 时，该值为 $2{,}147{,}483{,}648$ 字节，即 $2$ GiB。因此，“8 个激活专家”或“相同的激活参数量”本身无法确定缓存成本。M5.2 卡片仅在所有输入均有来源或被明确标记为假设时，才会使用此公式。

可执行小部件检查将谱系输出与确定性过滤器进行比较：

    node --experimental-strip-types course/viz/compute/architecture_genealogy.test.mjs

它检查稳定输出、年份过滤、重复性过滤、家族过滤以及未知源路径。

## 6。结束

**反直觉的问题。** 两个具有相同总参数量和激活参数量的模型，其 KV-cache 大小可能相差 10×，解码吞吐量可能相差 3×。哪些卡片字段可以解释这一差异？

**解答示例。** 首先关注注意力变体（attention variant）和 $h_{\mathrm{kv}}$：上述精确的缓存身份随 $h_{\mathrm{kv}}$ 线性变化。接着检查窗口方案、循环比率、精度 $b$，以及路由是否需要专家并行通信。总参数量和激活参数量描述了服务成本的不同部分；两者均不能替代缓存和路径字段。

**作业 A-M5。** 添加配置开关以复现三个示例卡片：一个类似 DeepSeek-V3 的 MLA+MoE+MTP 卡片，一个具有双 RoPE 基底的类似 Gemma-3 的局部/全局卡片，以及一个类似 Qwen3-Next 的 Gated DeltaNet/注意力 3:1 混合体。“类似”指代所选的教学维度，并非声称该示例模型复现了私有的生产实现。将同一语料库通过所有三个模型运行，并在一张表中报告损失、每秒令牌数和缓存字节数。M5.2 在标记作业完成前填充源卡片。

**核心检查。** 每个卡片仍然描述了一个基于前缀条件的下一个 token 分布。卡片记录了前缀如何存储和混合，如何选择激活计算，以及必须携带到下一个 token 的状态是什么。未解决的缺陷并非代数问题：缺失的源仍是一个未知字段。
