## 怎样用纸笔跟随

每篇保留完整正文、公式、原作业修正、数值表和曲线。遇到“纸笔停顿”先独立写下中间步骤，再展开答案。第 01 和 08 篇约 90-120 分钟，其余通常 60-90 分钟。先用四周完成一轮，再根据错误回读假设与推导。

1. 模型与定价：P/Q → 终值分布 → 高斯积分 → Delta/Gamma → BS PDE。
2. 数值方法：Taylor → 前向与中心差分 → 浮点误差 → complex-step → 复数 CDF/Hermite/P3。
3. 风险敏感度：Vega、Theta、Rho、股息 → Put-call 平价 → 单位与边界。
4. 高阶风险：Vanna、Vomma、Speed、Zomma、Charm、Color、Veta、Ultima → Hessian → IV 条件数。

## 数学、数值实现和市场解释怎样分别验证？

公式推导说明给定假设下的数学关系。80 位数值求导与样例扫描提供独立计算对照，不能变成全域证明。生产 Python/C++ 的舍入、复数 CDF 截断和并行行为还要单独检查。课程讨论的 Put 与其他 Greeks 不代表当前生产 API 已实现它们。

P 模型的概率是现实预测的目标，仍需数据估计与样本外校准；Q 下的概率是定价权重。即使数学推导或程序通过检查，也不能因此证明某个市场模型真实成立。

## 是否值得用 Lean？

值得做小规模试点，但不是当前学习与研发的前置条件。Lean 可以检查你明确写出的定义、假设与证明；它不会自动把自然语言讲义变成已证定理。建议先给试点 4-8 小时，选下列之一，并把依赖的假设写清楚：

- 第 07 篇：正部收益恒等式与 Put-call 平价。
- 第 02/06 篇：密度抵消恒等式，以及 Vega 与 Gamma 的关系。
- 第 04 篇：45° Taylor 多项式中的项抵消。多项式系数正确仍需另证余项界，才能推出误差阶。

有小定理通过后，再逐步扩到 Hermite 递推与导数。完整 BS 推导还涉及条件期望、Itô、换测度、随机积分、PDE 的存在唯一性条件，是更大的形式化项目。不要把未证明的关键结论当成假设，再称整条链已验证。

实数公式的 Lean 证明不会自动验证现有 NumPy 或 C++ SIMD 的执行。若要证明浮点程序，需另外连接实现语义、舍入模型、近似函数与误差界。[Lean 浮点文档](https://lean-lang.org/doc/reference/latest/Basic-Types/Floating-Point-Numbers/)介绍了这种逻辑模型；[布朗运动形式化论文](https://arxiv.org/abs/2511.20118)展示了随机过程形式化所需的基础工作。以上工作规模判断是本课程的建议。

## 数值研发路线

先在 Python 中固定接口与独立参考，再用 NumPy 批量计算，最后讨论 C++ 并行与 SIMD。准确性、收敛阶、尾部/退化行为、吞吐量与并行效率要分别记录。解析 Greeks 是普通 BS 的首选；数值方法帮助核验公式，并为没有闭式解的模型做准备。

本系列补充原有四门课程：数值计算、BS 定价、IV 与 C++ 数值工程。它保留当前库的实现边界，给你继续研发所需的数学基础。
